# StatMuse Builder — project summary

_Last updated: 2026-11-18, v0.18.0_

## What it is

A one-page web tool that builds an NBA stat question ("Jayson Tatum points in
the 4th quarter vs Lakers in wins", "Celtics points leaders in wins last 10
games", "LeBron James game log last 5 games") and opens it on StatMuse
(`https://www.statmuse.com/nba/ask/<slug>`). It improves on
stat-muse-helper.vercel.app with more filters, autocomplete, a live preview of
the exact question and URL, copy buttons, and Recent / Pinned lists.

- Production: https://statmuse-builder.vercel.app
- Repo: https://github.com/AlexLCBranco/statmuse-builder (public). Every push
  to `main` deploys on Vercel.

## What it's not

Not part of the gauntlet and not a stone. A small standalone app. No backend,
no accounts, no StatMuse API: it only builds links. It does not check
StatMuse's answer.

## Stack

Vite, React 19, TypeScript (strict), CSS Modules + design tokens
(`src/styles/tokens.css`), Vitest (unit), Playwright (e2e), oxlint. No state
library. Fonts: Barlow Condensed, IBM Plex Sans/Mono (Google Fonts).

Layers: `app -> features -> lib -> domain -> styles`

- `domain/` — pure logic with unit tests:
  - `query.ts` — the `QueryState`, the question builder for all three kinds
    of question, mode switch, per-row reset, clear all, the filter warning
  - `availability.ts` — **what each mode offers** (which filters, stat chips
    and periods). This is where a StatMuse check result becomes a rule; to
    offer or hide something, change it here
  - `recent.ts` — Recent list, pins, recent players/teams, reading saved data
  - `defaults.ts` — default selections: what is saved, checking saved data,
    the starting query
  - `rotations.ts` — the Rotations button: rotationkit link for the
    player or team, and the 30 NBA tricodes
  - `subjectSearch.ts` — Player box suggestions: players and teams in one
    ranked list
  - `slug.ts`, `playerSearch.ts`, `teamSearch.ts`, `options.ts` (chips, teams)
  - `data/players.ts` — the 2026-27 player list (generated by
    `scripts/sync-players.mjs`)
- `lib/` — browser helpers: safe localStorage, clipboard, build info.
- `features/` — question card; filters (chips and switches, player and team
  comboboxes, their shared dropdown `SuggestionList`); Recent + Pinned list;
  the default-selections gear and popover.
- `app/` — the page; holds the one `QueryState`.
- `reference/statmuse-builder.html` — the original single-file build this was
  ported from.

## What works now (v0.18.0)

- **Back-to-back preset** (v0.18.0, SM-3): a "Back-to-back" row (Any / 2nd
  night) in the Court/Result line adds "on the second night of a back to
  back" after the vs/without parts and before the result, in every mode
  (player, team in the Player box, team and league leaders, game log).
  StatMuse reads it as "no rest" (0 days). Saved with the default selections;
  has its own ✕. "1st night" is not offered: StatMuse misread every phrasing
  tried (see "Checked 2026-11-18")
- **Phone-usable** (v0.17.0, SM-1): checked at 390x844 with touch by a
  `phone` Playwright project (`e2e/phone.spec.ts`, runs by default next to
  desktop, locally and in `e2e:prod`): no sideways scroll in any state
  (screenshots saved as test artifacts), 44px+ tap targets, Ask on the first
  screen, and a question built by tapping gives the same link as on desktop.
  Tooltips that carry information open on a tap and close on a tap outside
  (`features/tip/TapTip`): the version badge (commit, build time) and a ☆
  when Pinned is full. The keyboard shrinks the page
  (`interactive-widget=resizes-content`) and dropdowns measure the visual
  viewport, so they stay above it. Desktop is unchanged
- **Pinned searches in the empty box** (v0.16.0): focused and empty, the
  Player and Team boxes list "Pinned searches" first (this mode's pins, max
  5), then recent players/teams, then recent searches. Players and teams of
  pinned searches count as recent names too. Rules: `boxRecents` in
  `domain/recent.ts`
- **Dropdowns float over the page** (v0.16.0): a suggestion list is
  `position: fixed`, placed from its box (`SuggestionList`). It no longer
  makes the builder column taller, follows its box while a column scrolls,
  and opens upward when there is little room below (Opponent at 1366x768);
  its height is capped to the room there
- **Swap players** (v0.15.0): "⇄ Swap players" right after "Clear all"
  swaps the Player and Vs player boxes ("Luka Doncic stats vs Devin Booker"
  -> "Devin Booker stats vs Luka Doncic"); every other filter stays. Shown
  only when both boxes are filled (hidden, never disabled), so never in Team
  leaders. Rules: `canSwapPlayers` / `swapPlayers` in `domain/query.ts`.
  At 1920px the row (Ask, Copy x2, Clear all, Swap, Rotations with a long
  name) is one line

- **Teams in the Player box** (v0.15.0): in Player mode the box also
  suggests the 30 StatMuse nicknames (marked "Team"), mixed with players by
  match quality (`domain/subjectSearch.ts`); any typed team works. A team
  there asks for team stats with every filter: "Timberwolves stats without
  Anthony Edwards this season". Rotations then opens the team page. Team
  leaders mode is unchanged (a team there gives its top players)

- **Rotations button** (v0.14.0): after "Clear all", a link (new tab) to
  the same player or team on rotationkit, so one search gives both links.
  Player mode (both views): "<name> rotations ↗" →
  `rotationkit.vercel.app/#/player?name=<name>` (the typed name counts).
  Team leaders: "<team> rotations ↗" → `#/team/<TRICODE>`. League or an
  empty box: "Rotations ↗", disabled. No filters go across. A long name
  wraps inside the button on a phone. `e2e:prod` also checks that
  rotationkit opens Anfernee Simons' page, not "No rotation data"

- **Pressed buttons are orange, not white** (v0.13.0): a pressed chip or
  switch has a dark orange tint, an accent-orange edge and light orange text
  (`--color-selected`, `--color-selected-ink`, `--color-selected-line`). A
  pressed "Any" / "Full game" has the edge and text but no tint

- **Three kinds of question**, picked with two switches above the first row:
  - Player / Averages: "LeBron James points in wins last 10 games"
  - Player / Game by game: "LeBron James game log in wins last 5 games" (one
    row per game on StatMuse). Offers exactly what Averages offers (v0.12.0):
    every stat, filter and period. "All stats" is a plain "game log"; one
    stat goes in front ("LeBron James points game log last 5 games")
  - Team leaders: "Celtics points leaders in the 4th quarter in wins last 10
    games" (a ranked list). The first row is a team box, with "League (NBA)"
    first for league-wide leaders. No "All stats", Turnovers, Vs player or
    Without; League also has no "last N games"
  Switching mode keeps every filter (a hidden one is only left out of the
  question) and each mode remembers its own player/team
- Starts empty: no player, "All stats", every filter on "Any" (the "factory
  defaults")
- **Default selections** (v0.11.0): a gear button at the right end of the
  mode/view line opens a small popover with "Set current selection as
  default" and "Reset to factory defaults"; the pressed button says "Saved" /
  "Reset done" for 1.5s. It closes on a click outside and on Escape, and
  floats over the page (no extra height). Saved: mode, view, stat, quarter,
  court, result, period and a custom "last N" (`smb.defaults`, with
  `version: 1`). Never saved: player, team, opponent, vs player, without.
  On load the saved rows are pressed; a corrupt entry, another version, or a
  value that is no longer a chip falls back to the factory default for that
  row. Reset removes the key and puts the button rows (mode and view too)
  back at once, leaving the boxes alone. Rules in `domain/defaults.ts`
- Live question preview (sentence + exact URL)
- Player box with suggestions from 528 players on 2026-27 NBA rosters
  (synced 2026-11-18, after camp cuts; 622 in preseason; from ESPN's public roster API; `npm run sync:players`
  refreshes it); any typed name works. Arrow keys + Enter pick a suggestion;
  Enter with a player chosen sends the question
- **Recents in the first box**: focused and empty, the player box lists
  "Recent players" (max 5; picking one fills only the player) and "Recent
  searches" (max 5; picking one loads the whole query). One letter typed and
  it is the normal suggestion list. The team box does the same with recent
  teams / leaders searches, followed by the full team list
- Chips: stat (all / points / rebounds / assists / FGA / FGM / 3PA / 3PM /
  steals / blocks / turnovers / minutes), quarter/half, home/away,
  wins/losses, period (last 5/10/20, this season, last season, playoffs,
  career) + custom "last N games" (1–82, wins over the chips)
- Opponent box: a dropdown you can type into (nickname or city); only a real
  team is kept
- Vs player and Without boxes (player mode, both views)
- **Clear**: "Clear all" empties the boxes, puts the filter rows back to the
  saved defaults (factory ones when none are saved), keeps the current mode
  and view, and focuses the first box; each filter has a small ✕ that shows
  only when it is off its factory default ("Any" / "All stats") and resets
  just that filter to it (Period's also clears "last N")
- Ask StatMuse (a real link, new tab), Copy question, Copy link.
  **Ctrl+Enter** (Cmd+Enter on Mac) anywhere presses Ask
- A note under the question ("StatMuse may not understand this many
  filters") when Vs player and Without are both set and 4+ filters are active
- Recent: last 12 sent questions in localStorage; Edit loads one back, ✕
  removes it. **Pinned**: ☆ on a Recent row moves it to a Pinned group above
  (max 12, never expire, not counted in the 12 recents, saved under
  `smb.pinned`); ★ sends it back to Recent
- **Full-width layout with big click targets** (v0.9.0): the page starts at
  the left edge (24px padding) and uses the whole window; the builder takes
  the space, Recent is a fixed 380px column on the right (below the builder
  under 1100px). Chips and switches are 48px tall with 17px text, action
  buttons and text boxes 52px, Recent rows 52px with 44x44 star / ✕ / Edit
  buttons set apart. Sizes are tokens (`--control-h`, `--input-h`, `--hit`).
  At 1920px every chip group is on one line and everything fits one screen.
  At 1366x768 Stat and Period wrap to two lines. Fits a 375px phone with no
  sideways scroll
- **The page never scrolls** (v0.10.0): the app is exactly the window height
  (`100dvh`, `overflow: hidden` on html/body). The Recent column fills the
  height; the "Recent" heading stays put and only its list scrolls (Pinned
  does the same, up to 45% of the column). A builder that does not fit
  (1366x768) scrolls inside its own column. In one column (under 1100px,
  phones) the area under the header scrolls as one. Scrollbars are slim and
  in the theme's line colour
- **Version badge**: "v0.8.0" small and muted in the bottom-right corner,
  with the commit and build time in its tooltip; the same three values are
  served at `/version.json` (no-cache on Vercel, via `vercel.json`).
  `vite.config.ts` reads them at build time. CI (`.github/workflows/ci.yml`)
  runs `npm run check-version`, which fails a push that changes the app
  without raising the version, then `npm run check`. `npm run wait-live`
  waits until the live site serves the new version
- Dark theme only (the opt-in light theme was removed in v0.7.0)
- Old Recent entries (saved before v0.7, without mode/team/view) load as
  player mode, averages
- Tests: 219 unit tests (domain + the version check), 64 Playwright e2e tests (56 desktop, 8 phone; two run only in `e2e:prod`). `npm run check`
  runs lint + typecheck + unit + e2e; `npm run e2e:prod` runs e2e against the
  live site

## StatMuse compatibility

Rule: a chip or filter is only offered in a mode where a real StatMuse page
answered that phrasing correctly. The rules live in `domain/availability.ts`.

## Open problems

- StatMuse now hides the result table behind a sign-up prompt after a few
  questions, so checks past that point only see the answer sentence.
- "Turnovers leaders" is ranked fewest-first on StatMuse, so there is no
  turnovers chip in leaders mode. A different phrasing ("most turnovers")
  might work but has not been checked.
- "FGA leaders" ranks by season total while the other leader stats are per
  game. Offered as is.
- Stacking too many filters can lose StatMuse: team + vs player + without +
  wins got no answer, though each 4-filter subset did. The app now warns.
- "This season" returns last season's numbers until the new season has games.
- The player list is a snapshot of 2026-27 rosters (incl. two-way players);
  later signings get no suggestions until re-synced (typing still works).
- At 1366x768 the filter rows do not all fit (the 48px+ targets need more
  height than that window has), so the builder column scrolls there; the
  last rows are below its fold until you scroll it.
