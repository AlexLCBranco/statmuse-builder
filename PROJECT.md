# StatMuse Builder — project summary

_Last updated: 2026-11-12, v0.9.0_

## What it is

A one-page web tool that builds an NBA stat question ("Jayson Tatum points in
the 4th quarter vs Lakers in wins", "Celtics points leaders in wins last 10
games", "LeBron James game log last 5 games") and opens it on StatMuse
(`https://www.statmuse.com/nba/ask/<slug>`). It improves on
stat-muse-helper.vercel.app with more filters, autocomplete, a live preview of
the exact question and URL, copy buttons, and Recent / Pinned lists.

- Production: https://statmuse-builder.vercel.app
- Repo: https://github.com/AlexLCBranco/statmuse-builder (public). Every push
  to `main` deploys on Vercel.

## What it's not

Not part of the gauntlet and not a stone. A small standalone app. No backend,
no accounts, no StatMuse API: it only builds links. It does not check
StatMuse's answer.

## Stack

Vite, React 19, TypeScript (strict), CSS Modules + design tokens
(`src/styles/tokens.css`), Vitest (unit), Playwright (e2e), oxlint. No state
library. Fonts: Barlow Condensed, IBM Plex Sans/Mono (Google Fonts).

Layers: `app -> features -> lib -> domain -> styles`

- `domain/` — pure logic with unit tests:
  - `query.ts` — the `QueryState`, the question builder for all three kinds
    of question, mode switch, per-row reset, clear all, the filter warning
  - `availability.ts` — **what each mode offers** (which filters, stat chips
    and periods). This is where a StatMuse check result becomes a rule; to
    offer or hide something, change it here
  - `recent.ts` — Recent list, pins, recent players/teams, reading saved data
  - `slug.ts`, `playerSearch.ts`, `teamSearch.ts`, `options.ts` (chips, teams)
  - `data/players.ts` — the 2026-27 player list (generated by
    `scripts/sync-players.mjs`)
- `lib/` — browser helpers: safe localStorage, clipboard, build info.
- `features/` — question card; filters (chips and switches, player and team
  comboboxes, their shared dropdown `SuggestionList`); Recent + Pinned list.
- `app/` — the page; holds the one `QueryState`.
- `reference/statmuse-builder.html` — the original single-file build this was
  ported from.

## What works now (v0.9.0)

- **Three kinds of question**, picked with two switches above the first row:
  - Player / Averages: "LeBron James points in wins last 10 games"
  - Player / Game by game: "LeBron James game log in wins last 5 games" (one
    row per game on StatMuse). No Stat row; only Quarter, Opponent, Result and
    Period (Last 5/10/20, Last season, last N) are offered
  - Team leaders: "Celtics points leaders in the 4th quarter in wins last 10
    games" (a ranked list). The first row is a team box, with "League (NBA)"
    first for league-wide leaders. No "All stats", Turnovers, Vs player or
    Without; League also has no "last N games"
  Switching mode keeps every filter (a hidden one is only left out of the
  question) and each mode remembers its own player/team
- Starts empty: no player, "All stats", every filter on "Any"
- Live question preview (sentence + exact URL)
- Player box with suggestions from 622 players on 2026-27 NBA rosters
  (synced 2026-10-17 from ESPN's public roster API; `npm run sync:players`
  refreshes it); any typed name works. Arrow keys + Enter pick a suggestion;
  Enter with a player chosen sends the question
- **Recents in the first box**: focused and empty, the player box lists
  "Recent players" (max 5; picking one fills only the player) and "Recent
  searches" (max 5; picking one loads the whole query). One letter typed and
  it is the normal suggestion list. The team box does the same with recent
  teams / leaders searches, followed by the full team list
- Chips: stat (all / points / rebounds / assists / FGA / FGM / 3PA / 3PM /
  steals / blocks / turnovers / minutes), quarter/half, home/away,
  wins/losses, period (last 5/10/20, this season, last season, playoffs,
  career) + custom "last N games" (1–82, wins over the chips)
- Opponent box: a dropdown you can type into (nickname or city); only a real
  team is kept
- Vs player and Without boxes (player mode, averages)
- **Clear**: "Clear all" resets everything except mode and view and focuses
  the first box; each filter has a small ✕ that shows only when it is off its
  default and resets just that filter (Period's also clears "last N")
- Ask StatMuse (a real link, new tab), Copy question, Copy link.
  **Ctrl+Enter** (Cmd+Enter on Mac) anywhere presses Ask
- A note under the question ("StatMuse may not understand this many
  filters") when Vs player and Without are both set and 4+ filters are active
- Recent: last 12 sent questions in localStorage; Edit loads one back, ✕
  removes it. **Pinned**: ☆ on a Recent row moves it to a Pinned group above
  (max 12, never expire, not counted in the 12 recents, saved under
  `smb.pinned`); ★ sends it back to Recent
- **Full-width layout with big click targets** (v0.9.0): the page starts at
  the left edge (24px padding) and uses the whole window; the builder takes
  the space, Recent is a fixed 380px column on the right (below the builder
  under 1100px). Chips and switches are 48px tall with 17px text, action
  buttons and text boxes 52px, Recent rows 52px with 44x44 star / ✕ / Edit
  buttons set apart. Sizes are tokens (`--control-h`, `--input-h`, `--hit`).
  At 1920px every chip group is on one line and everything fits one screen.
  At 1366x768 Stat and Period wrap to two lines and the page scrolls
  vertically (it no longer fits one screen at that size). Fits a 375px phone
  with no sideways scroll
- **Version badge**: "v0.8.0" small and muted in the bottom-right corner,
  with the commit and build time in its tooltip; the same three values are
  served at `/version.json` (no-cache on Vercel, via `vercel.json`).
  `vite.config.ts` reads them at build time. CI (`.github/workflows/ci.yml`)
  runs `npm run check-version`, which fails a push that changes the app
  without raising the version, then `npm run check`. `npm run wait-live`
  waits until the live site serves the new version
- Dark theme only (the opt-in light theme was removed in v0.7.0)
- Old Recent entries (saved before v0.7, without mode/team/view) load as
  player mode, averages
- Tests: 151 unit tests (domain + the version check), 26 Playwright e2e tests. `npm run check`
  runs lint + typecheck + unit + e2e; `npm run e2e:prod` runs e2e against the
  live site

## StatMuse compatibility

Rule: a chip or filter is only offered in a mode where a real StatMuse page
answered that phrasing correctly. The rules live in `domain/availability.ts`.

## Open problems

- StatMuse now hides the result table behind a sign-up prompt after a few
  questions, so checks past that point only see the answer sentence.
- "Turnovers leaders" is ranked fewest-first on StatMuse, so there is no
  turnovers chip in leaders mode. A different phrasing ("most turnovers")
  might work but has not been checked.
- "FGA leaders" ranks by season total while the other leader stats are per
  game. Offered as is.
- Stacking too many filters can lose StatMuse: team + vs player + without +
  wins got no answer, though each 4-filter subset did. The app now warns.
- "This season" returns last season's numbers until the new season has games.
- The player list is a snapshot of 2026-27 rosters (incl. two-way players);
  later signings get no suggestions until re-synced (typing still works).
- At 1366x768 the filter rows no longer fit one screen (Period ends about
  170px below the fold): the 48px+ targets asked for in v0.9.0 need more
  height than that window has.
- The version badge is fixed to the window corner, so on a page long enough
  to scroll, content passes under it.
- The empty box's recent groups are built from Recent only; a pinned search
  does not appear there.
